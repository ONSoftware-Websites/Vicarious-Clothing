# SellerHQ → Vicarious Clothing → Vinted integration map

## Goal

SellerHQ should be the stock control source. Vicarious Clothing should receive website-ready products from SellerHQ. Vinted should be handled through the official Vinted Pro Integrations API if Vicarious/Henry is allowlisted for Vinted Pro.

Do not put shared API secrets in frontend React code. The website endpoint is server-to-server only.

## Current repo link

The Vicarious website now accepts SellerHQ product sync requests at:

```text
POST https://vicariousclothing.co.uk/api/integrations/sellerhq/products
PATCH https://vicariousclothing.co.uk/api/integrations/sellerhq/products
```

Authentication:

```http
Authorization: Bearer <SELLERHQ_API_KEY>
```

or:

```http
X-SellerHQ-Api-Key: <SELLERHQ_API_KEY>
```

Required Vercel variable on the Vicarious website:

```env
SELLERHQ_API_KEY=replace-with-at-least-32-random-bytes
```

## Canonical identity mapping

| SellerHQ field | Vicarious field | Purpose |
| --- | --- | --- |
| `code` | `prdCode` | Permanent hidden cross-system key. Visible only in admin inventory. |
| `sku` | source SKU/reference | Used only if it already starts with `VC-`; otherwise Vicarious keeps its own generated SKU. |
| `id` | fallback `prdCode` | Used only if `code` is missing. |
| generated by website | `sku` | Vicarious public/internal website SKU, e.g. `VC-000123`. |
| generated by website | `slug` | Customer-facing product URL slug. |

The important rule is: **SellerHQ `code` is the source-of-truth product reference**. Once the website product is linked by `prdCode`, future syncs update the same website product rather than creating a duplicate.

| SellerHQ product | Website product |

## Status map

| SellerHQ status | Website status |
| --- | --- |
| `Listed` or request `publish: true` | `AVAILABLE` |
| `Unlisted`, `Draft`, `Relisting Required`, `Issue` | `DRAFT` |
| `Reserved`, `Awaiting Shipping`, `In Shipping` | `RESERVED` |
| `Sold` or `saleDate` present | `SOLD` |
| `Removed`, `Returned`, `Archived` | `ARCHIVED` |

  -d '{
    "publish": true,
    "product": {

## Vinted route

Vinted should not be integrated by scraping private browser endpoints or using a cookie-based unofficial wrapper. The safe route is Vinted Pro Integrations.

As of August 2026, Vinted Pro Integrations supports item management, webhooks, order management, ontology/category mapping, and sandbox/dev mode, but access is limited to allowlisted Vinted Pro businesses.

Vinted Pro concepts to map:

| SellerHQ/Vicarious | Vinted Pro concept |
| --- | --- |
| product title/name | item title/name |
| description | item description |
| brand | Vinted brand field / ontology value |
| category | Vinted ontology category |
| size | Vinted ontology size |
| condition | Vinted condition enum |
| colour | Vinted colour/attribute |
| images | Vinted item photos |
| listingPrice | Vinted item price |
| code / prdCode | internal correlation metadata if supported, otherwise local connector table |

Recommended Vinted connector tables in SellerHQ:

```sql
create table marketplace_connections (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null,
  marketplace text not null,
  status text not null default 'inactive',
  access_key text,
  signing_key_encrypted text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table marketplace_listing_links (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null,
  product_id uuid not null,
  marketplace text not null,
  external_item_id text,
  external_url text,
  status text not null default 'draft',
  last_synced_at timestamptz,
  last_error text,
  unique (business_id, product_id, marketplace)
);
```

## Recommended build order

1. Website inbound sync endpoint. Done in Vicarious repo.
2. SellerHQ server-side sync function that calls the website endpoint. Do not expose `SELLERHQ_API_KEY` in browser code.
3. SellerHQ UI button: “Publish to Vicarious website”.
4. SellerHQ sync log table so Henry can see success/failure.
5. Vinted Pro connector once Henry has allowlisted Vinted Pro API access.
6. Vinted webhooks into SellerHQ so sales/status changes update SellerHQ and then delist/update the website.

## Important constraint

If SellerHQ stays as a browser-only Vite app, it cannot securely call the website integration endpoint directly. Use one of these instead:

- Vercel `/api/...` function inside SellerHQ;
- Supabase Edge Function;
- a small Node backend;
- or a manual export/import workflow until a backend exists.
